## ひとことで

AI エージェントは、「〇〇をやっておいて」という指示を受けて、自分で手順を考え、検索・表計算・社内システムなどの道具を使い分けながら、仕事を最後までやろうとする AI です。質問に一回答えて終わるチャットとは違い、「調べる → 作る → 確かめる → 直す」を何度も繰り返します。

## 仕組みをかんたんに

中身は、文章を理解して書ける大規模言語モデル（LLM）に、次の 3 つを足したものです。

- **道具**: Web 検索、ファイルの読み書き、メール、社内システムの API など。AI は「この道具をこの条件で使う」と決めて呼び出します。道具をつなぐ共通の決まりとして [MCP](topic:tools-mcp) が広く使われています。
- **繰り返し（ループ）**: 道具の結果を見て、次に何をするかを考え直します。うまくいかなければやり方を変えます。
- **記憶と手順書**: 作業の途中経過や、会社ごとのやり方（手順書・ルール）を読みながら進めます。

画面のスクリーンショットを見てマウスとキーボードを操作する「コンピューター操作型」のエージェントもあり、API が無い古いシステムでも動かせる点が注目されています。ただし API 経由に比べると遅く、失敗もしやすいのが現状です。

## いま何が起きているか

2026 年は「エージェントが試験運用から実務に入った年」と言われています。大きな流れは次のとおりです。

- **業務ソフトへの組み込み**: 会計・人事・顧客管理などの業務ソフトに、エージェント機能が最初から入るようになってきました。自社で一から作るより、使っているソフトの機能として使う会社が増えています。
- **関心が「賢さ」から「確実さ」へ**: できることの幅より、毎回同じ品質で終わらせられるか、途中で何をしたか後から確かめられるか、が問われるようになりました。業者側も、正確さ・説明のしやすさ・セキュリティを課題に挙げています。
- **長い仕事を任せる**: 数分で終わる作業だけでなく、数時間かかる調べものや資料作り、プログラムの修正を任せる使い方が広がっています。特にソフトウェア開発では日常的な道具になりました（[AI コーディング](topic:coding)）。
- **複数のエージェントの分業**: 「調べる係」「書く係」「確認する係」のように役割を分けて組ませる作り方が一般的になっています。

## どう使われているか

| 使い方 | 誰が・どこで | 何が良くなるか |
| --- | --- | --- |
| 調査レポートの下書き | 企画・営業・経営企画 | 何十ものページを読んで要点と出典をまとめる時間が短くなる |
| 問い合わせの一次対応と手続き | カスタマーサポート | 回答だけでなく、注文の確認や変更受付まで自動で進められる |
| 経費・請求書のチェック | 経理 | 規程と照らし合わせ、怪しいものだけ人に回せる |
| 社内システムへの転記 | 事務・バックオフィス | メールや PDF の内容を読み取り、決まった画面に入力する手間が減る |
| プログラムの修正とテスト | 開発チーム | 小さな修正を任せ、人はレビューに集中できる |
| 定例の数字集計と報告 | 管理部門 | 毎週・毎月の集計表と説明文を自動で用意できる |

## ビジネスへの応用

- [バックオフィス・士業](industry:backoffice): 請求書の照合、契約書の条文チェックの下準備、社内申請の振り分け。
- [ソフトウェア開発・IT](industry:software): 不具合修正、テスト作成、社内ツールづくり、運用の定型作業。
- [マーケティング・営業](industry:marketing): 見込み客の下調べ、提案書の下書き、競合の動きのまとめ。
- [小売・EC](industry:retail): 問い合わせ対応から返品・交換の受付まで、商品情報の更新作業。
- [製造業](industry:manufacturing): 保全記録や技術文書を調べての一次回答、発注・在庫の確認作業。
- [物流・運送](industry:logistics): 配送状況の問い合わせ対応、伝票の内容をシステムへ入力する作業。
- [金融・保険](industry:finance): 申込書類の不備チェック、調査資料の下書き（最終判断は人）。

## 始め方と費用感

1. **既製サービスで試す**: 生成 AI の業務向けプラン（2026 年時点で 1 人あたり月数千円程度〜）に付いている調査機能・エージェント機能を、まず個人の作業で使ってみます。「毎週やっている調べもの」のような、失敗しても困らない仕事が向いています。
2. **自社データとつなぐ**: 社内のファイル置き場やチャット、業務ソフトとつなぎます。業務ソフト側にエージェント機能があれば、それを使うのが早道です。[RAG](topic:rag) で社内文書を読ませる段階でもあります。
3. **作り込む**: 自社の業務手順に合わせたエージェントを作ります。API 料金は使う量で大きく変わり、小さな業務なら月数万円程度から、全社展開では開発費を含めて数百万円規模になることもあります（2026 年時点の目安）。

どの段階でも、「どこまで AI に任せ、どこで人が確認するか」を先に決めておくことが大事です。

## 注意点・リスク

- **間違いが連鎖する**: 手順の途中で間違えると、その後の作業が全部ずれます。結果だけでなく途中の記録（ログ）を残し、確かめられるようにします。
- **権限の与えすぎ**: 送信・削除・支払いなど取り消せない操作は、人の承認を挟みます。エージェント用のアカウントには必要最小限の権限だけを渡します。
- **プロンプトインジェクション**: 読み込んだ Web ページやメールに「この指示に従え」と書かれていて、AI がそれに従ってしまう攻撃です。外から来た文章は「データ」として扱う設計にします（[安全性・ガバナンス](topic:safety)）。
- **費用の読みにくさ**: 何度も考え直すぶん、1 回の作業で使う量がぶれます。上限を設定しておきます。
- **「全部自動」を急がない**: 人の仕事を丸ごと置き換えるより、下準備を任せて人が仕上げる形のほうが、現時点では成果が出やすいです。
